SessionManager为什么不需要单例模式?
  因为每个Activity都可以创建自己的SessionManager实例，而它们实际上共享同一个SharedPreferences文件。这样设计的好处是每个Activity可以独立管理自己的会话状态，但所有实例都指向同一个数据源。
SessionManager的工作原理：
```java
// SessionManager 不是传统意义上的"对象持久化"
// 而是基于 Android 系统的 SharedPreferences 机制
public class SessionManager {
    private SharedPreferences preferences;  // 这个才是真正的"数据库"
}
```
多个SessionManager的真相：
```java
// 在 MainActivity 中
SessionManager sessionManager1 = new SessionManager(this);

// 在 LoginActivity 中  
SessionManager sessionManager2 = new SessionManager(this);

// 这确实创建了两个不同的 SessionManager 对象！
// 但是它们访问的是同一个 SharedPreferences 文件
```
图解：
```plaintext
📱 Android 系统存储
├── /data/data/com.liu.coursedesign/shared_prefs/
│   └── user_session.xml  ← 真正的数据存储位置
│
📱 应用内存中
├── MainActivity 
│   └── sessionManager1 实例 ────┐
│                              │ 
└── LoginActivity              │ 都指向同一个文件
    └── sessionManager2 实例 ────┘
```
